## 1. Frontend Architecture

- **Stack:** React 18.3 + TypeScript (strict) + Vite 6 + Tailwind CSS v4 + shadcn/ui (Radix primitives) + Lucide icons + Sonner toasts. PWA (manifest + service worker).
- **Entry:** `src/main.tsx` → `src/app/App.tsx` (`AuthProvider` → `RouterProvider` → `Toaster`).
- **Routing:** React Router 7 `createBrowserRouter` in `src/app/routes.tsx`. Public website at `/` (indexable, CMS-driven), shared `/login`, `/admin/*` (14 nav areas incl. Website + System), `/teacher/*` (11), `/student/*` (11), `/preview` (admin CMS draft preview shell), `*` → login.
- **State:** Auth via `contexts/AuthContext.tsx` (Supabase browser session, Bearer token); per-page local state; SSE notifications via `hooks/useRealtimeNotifications.ts`.
- **API client:** `lib/api.ts` — thin fetch wrapper (~90 functions), Bearer from `getSupabaseAccessToken()`, 3-retry exponential backoff on 429/502/503/504, `VITE_API_URL || '/api'` base. Exported `publicSite` client for `/public/*` and `uploadFile(file, path)`.
- **SEO:** `components/public/useSeo.ts` sets per-route title/description/keywords/robots/canonical + OpenGraph/Twitter tags; public pages indexable (`index, follow` in `index.html`), protected portals `noindex` via `useSeo`. CMS `seo` section supplies site-wide defaults (`applySeoDefaults`). Sitemap generated at build (`scripts/generate-sitemap.cjs` from `SITE_URL || VITE_SITE_URL`).
- **Role shells:** `components/layout/{Admin,Teacher,Student}Layout.tsx` — hand-rolled sidebar + sticky header + `NotificationBell` + user menu. Admin topbar has debounced `GlobalSearch` (students/teachers/courses/notices/events via `/admin/search`) and a Ctrl+K `CommandPalette` (shared `useGlobalSearch` hook).
- **Types:** `types/auth.ts` (live), `types/index.ts` + `types/models.ts` (duplicate legacy), `types/supabase.ts` (unused generated).
- **Dead scaffolding:** removed during the production pass — `src/app/apps/*`, root `apps/{admin,teacher,student}/` stubs, `packages/shared-ui`, `packages/utilities`. `packages/shared-types` is live (backend auth types).

## 2. Backend Architecture

- **Stack:** Node ≥20, Express 5, TypeScript ESM (tsx dev runner), Drizzle ORM + postgres.js against Supabase PostgreSQL 17. Entry: `apps/backend/src/server.ts`.
- **Middleware order:** helmet (CSP off) → CORS (origin allowlist, dev debug logs only in dev) → json/urlencoded (10mb) → rate limit (500/15min API, 20/15min auth) → dev request logger → private-upload authorized endpoint → static uploads (attachment, nosniff, `/private/` forbidden) → `/api` router → notFound → errorHandler (PG error-code map, safe messages).
- **Route mounting** (`routes/index.ts`): `/api/health`, `/api/status`, `/api/auth`, `/api/admin` (+offlineMock), `/api/teacher` (+offlineMock), `/api/student` (+offlineMock), `/api/upload`, `/api/notifications`, `/api/public` (public site), `/api/admin/site` (public-site CMS, `siteContent.ts` behind `authenticate, requireAdmin`). Offline mock is dev-only, fail-closed 503 in prod.
- **Public API** (`routes/public.ts`): `GET /status`, `GET /config` (navigation + whatsapp + social + homepage mode), `GET /home`, collection endpoints `/courses /faculty /notices /events /events/:slug /admissions /fees /achievements /results /gallery /reviews /blog /blog/:slug /faqs /pages /pages/:slug`, sandboxed `/custom/:slug` + `/custom/:slug/files/*path`, `POST /enquiries` (rate-limited 10/15min), `POST /reviews` (consent + rate-limited 5/15min, lands `pending`, admin notified). Never serves CMS drafts; draft custom pages require an HMAC preview token.
- **Public-site CMS** (`routes/siteContent.ts`): generic CRUD factory (list/search/status filter/create/update/publish/unpublish/archive) for admissions, fees, achievements, results, gallery, blog, FAQs; reviews moderation; site-pages (JSON blocks); homepage-sections; navigation (reserved slugs + system items protected); custom-pages lifecycle (create/duplicate/publish/unpublish/archive/versions/restore/validate + file save/delete + HMAC preview token). Express 5 route patterns use named splats (`*path`) — `:path(*)` regex syntax is invalid under path-to-regexp v8.
- **Router conventions:** each router applies `authenticate` + role guard at top; `asyncHandler` wraps every handler; `validate(schema)` (express-validator) on high-risk writes; `ApiError(status, message)`; `logAudit()` best-effort writes to `audit_logs` (admin only today).
- **Services:** `authService.ts` (identity resolution), `authorization.ts` (batch/object-level assertions, fail-closed), `accountProvisioningService.ts` (Supabase admin createUser + transactional DB insert + compensating delete).
- **Storage:** `lib/storage.ts` — Cloudinary-first (`coaching/materials` folder) with local-disk fallback; injectable uploader for tests.
- **SSE:** `ws/wsManager.ts` — in-memory client registry, `emitToUser(s)`, `emitToRole`; used for notifications.

## 3. Database Architecture

Supabase PostgreSQL, 41 tables, Drizzle schema in `apps/backend/src/db/schema.ts` (single source of truth), migrations in `supabase/migrations/0000–0009` (RLS enabled on all tables; runtime uses admin connection).

Key tables: `users` (+role/status/soft-delete), `profiles` (Supabase identity link), `student_profiles`, `teacher_profiles`, `courses→subjects→chapters`, `batches` (+`batch_students`/`batch_teachers` M:N), `materials` (cloudinary_id), `live_classes`, `tests`→`questions`/`test_results`/`test_answers`, `assignments`→`assignment_submissions`, `doubts`→`doubt_replies`, `fees`→`payments`, `attendance_sessions`→`attendance_records`, `audit_logs`, `settings` (key/value, hosts CMS draft/live JSON), `notifications`, `auth_events`, `notices`, `events`, `enquiries`, `media_assets`, `cms_versions` (append-only CMS journal: section/content/action/actor/timestamp).

Public-site CMS tables (migration 0009): `site_pages` (JSON block content), `admissions`, `fee_structures`, `achievements`, `public_results`, `gallery_items`, `reviews` (moderated pending→approved), `blog_posts` (unique slug), `faqs`, `navigation_items` (`is_system` protected), `homepage_sections` (per-area config + featured ids), `custom_pages` (+`custom_page_files` with unique `page_id,path`, +`custom_page_versions` snapshots).

## 4. Authentication Flow

1. Login page (`/login`, email+password) → `supabase.auth.signInWithPassword` → `/auth/me` → role dashboard.
2. `AuthContext` restores session from Supabase localStorage, listens `onAuthStateChange`, `refreshUser()` calls `api.auth.me()`.
3. Backend `authenticate`: Bearer token → `supabase.auth.getUser` → `resolveSupabaseAuthUser` links via `profiles.supabase_auth_id` (fallback phone/email match), blocks non-active accounts (401), auto-creates role profile, logs `auth_events`.
4. Role resolution is **server-side only** (`users.role`); frontend guards are UX only.
5. Admin-created accounts are provisioned via service-role `createUser` + DB transaction (Phase E, implemented).

## 5. Authorization / RBAC

- **Route level:** `/api/admin` = `requireAdmin`; `/api/teacher` = teacher-or-admin; `/api/student` = student only; notifications/upload = authenticated.
- **Object level:** `services/authorization.ts` — `assertTeacherOfBatch`, `assertTeacherCanAccessStudent`, `assertTeacherCanAccessDoubt`, `assertTeacherOwnsTest`, `assertStudentCanAccessTest`, `assertStudentCanAccessMaterial`, `assertStudentCanAccessLiveClass`, `assertRecipientsScopedToTeacher`. Fail-closed, 404-over-403 for sensitive objects.
- **Known posture:** admin routes are role-guarded only (institute-wide by design); teacher routes check batch/ownership; student routes check batch/course membership.

## 6. Admin Architecture

Single SPA section under `/admin` with 14 nav areas: Dashboard, Students, Teachers, Courses, Batches, Materials, Tests, Fees, Live Classes, Broadcast, Website (CMS suite), Audit Logs, System Health, Settings. Server-side pagination everywhere; provisioning (create student/teacher with password), soft-delete, status toggles, batch member management, materials, fees+payments, broadcast, audit-logs with CSV export, settings (institute/notification/fee/security/maintenance). Students/Teachers support CSV export (`?all=true` server fetch). Website suite: JSON CMS editor with draft→publish lifecycle + version history/restore, responsive site preview (live/draft + section selector), notices/events CRUD, enquiries inbox, media library with usage-safe deletion, global search, system health.

## 6a. Public Website Architecture

Static-ish CMS-driven site served from the same SPA at `/` via `PublicLayout` (header/footer/social links, maintenance-mode banner — admins bypass; preview-aware nav). Pages: Home, Courses, Faculty, Notices, Events, Contact (enquiry form → `POST /public/enquiries`). Data flows through `/public/*`; the admin draft-preview (`/preview?page=&section=&draft=1`) loads the same pages in an iframe with drafts merged via `/admin/cms/preview` (admin-only). SEO: per-page titles/descriptions via `useSeo`, CMS `seo` section defaults via `applySeoDefaults`, `robots.txt` allows public paths (blocks `/admin /teacher /student /api /auth /preview`), `sitemap.xml` built at build time.

## 7. Teacher Architecture

`/teacher` with 11 items: Dashboard, My Batches, Materials, Live Classes, Tests (+question builder/publish/grading), Assignments (+grading), Doubts (batch-scoped, replies authorized), Analytics, Student Progress, Attendance (sessions per batch), Profile. All writes batch-scoped; test/submission grading owned.

## 8. Student Architecture

`/student` with 11 items: Dashboard (fee alert, stats, pending assignments, upcoming classes, results, attendance %), My Courses, Study Materials (batch/course-scoped), Live Classes (batch-scoped), Tests (timer, autosave, MCQ auto-grade, batch-scoped), Results, Assignments (+file upload), Doubts, Fees (+receipt), Notifications, Profile (+completion gate).

## 9. CMS Architecture

Settings-backed JSON CMS (`cms.home|seo|social|footer` with `.live`/`.draft` keys in `settings`). Admin suite under `/admin/website`: JSON editor (validated, sanitized, save draft → publish copies draft→live), draft preview iframe, notices/events CRUD with draft→published→archived lifecycle, enquiries inbox with status pipeline (new/read/resolved/archived), media library (Cloudinary metadata, alt text, reference-checked deletion against materials/events/CMS JSON). Every write is audit-logged. `cms_versions` append-only journal records every save/publish/restore snapshot; `POST /cms/versions/:id/restore` rolls draft AND live back to a snapshot (restore itself journaled). Public API serves live content only.

## 10. Media Architecture

Cloudinary configured + wired for material uploads (`lib/storage.ts`, `cloudinary_id` persisted on materials, deleted with materials). Media library (`media_assets` table) records every library upload with public_id/url/dimensions/alt text; deletion is reference-checked (materials/events/CMS JSON) and returns 409 with a usage summary when in use. Local fallback for materials; private student submissions on local disk behind authorized endpoint.

## 11. API Architecture

REST under `/api`. Public endpoints: `/health`, `/status`, `/public/*` (status/home/courses/faculty/notices/events/enquiries). Authenticated role routers: admin (incl. CMS suite + `/search` + `/system`)/teacher/student/notifications/upload/auth. Response envelope `{ success, data | error }`. Errors: 400/401/403/404/409/422/429/500 mapped consistently.

## 12. Deployment Architecture

- Frontend: Vercel (`vercel.json` SPA rewrite + security headers incl. CSP and `X-Frame-Options: DENY`).
- Backend: Render (`render.yaml`, pnpm, port from env) — not deployed in this session.
- DB: Supabase cloud (live; migrations 0001–0008 applied).
- Media: Cloudinary (live creds in `.env`).
- Build: `npm run build` = `generate-sitemap.cjs` (requires `SITE_URL`/`VITE_SITE_URL` for a real sitemap; writes placeholder otherwise) → `vite build` → `generate-precache.cjs` (PWA manifest).
